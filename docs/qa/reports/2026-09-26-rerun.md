## Review
**hybrid_launch::register_dbc_launch**: every claim was confirmed in code.
- Mint and supply: `mint` is `Account<Mint>`, so only the classic Token program is accepted (Token-2022 → 3007). Mint authority and freeze authority must be None, and supply must be exactly 1B × 10^decimals (`DbcMintRejected`).
- Pool linked to the mint (`DbcAccountInvalid` unless noted):
  - DBC owner, discriminator and length are checked.
  - `pool.base_mint == mint` and `pool.config == dbc_config`.
  - The pool creator must be the signer (`DbcCreatorMismatch`).
  - The pool must not be migrated (`DbcAlreadyGraduated`).
- Config: the allowlist is checked first (`DbcConfigNotApproved`). Then wSOL quote, fixed 1B pre/post supply, immutable authority and leftover receiver = the `dbc_buffer` PDA.
- Create-only: LaunchConfig is `init`, so there is one per mint. It never references the hybrid_launch launch vault; it creates the buffer ATA idempotently.
- No fee input: params are only {ratio_whole_tokens, collection_size}.
- **The fee IS derived from the ratio tier**: `validate()` → `checked_fee_for_ratio` → `fee_lamports`. The fee recipient is the `PLATFORM_FEE_RECIPIENT` constant, with the same checks as launch.
- Notes (Info, not bugs):
  - (a) On DBC configs, `launch_vault` / `launch_destination` are repurposed (DBC_POOL_AUTHORITY / pool.base_vault, bumps 0). hybrid_vault doesn't read them, but any off-chain tool that assumes they're hybrid_launch PDAs would be wrong.
  - (b) `base_vault` holding the full supply is not checked (DBC guarantees it at creation).
  - (c) The devnet allowlist includes the third-party template 5L1MfYm4…, which can never pass the leftover check (harmless).

**hybrid_vault::expire_requests(count)**: claims confirmed, no issues.
- `count` must be in 1..=7 (`MAX_EXPIRE_PER_CALL`), and remaining accounts must be exactly count × 7 (`ExpireBatchInvalid`).
- Each request goes through `expire_one`, the same core as `expire_request`. Each request PDA is re-derived from `next_settle_seq`, so requests must be the FIFO head in order and can't repeat. Owner, discriminator, user, randomness, rand_lock, mint escrow PDA and user_token mint/owner are checked.
- The only arg is `count`; there is no ratio, fee or mint input. The ratio comes from `exit_view` and the mint is pinned to `vault.mint`. The batch is all-or-nothing, and invariants are checked at the end.

**Graduation (test build)**: a native launch (`dbc_pool` = default) with a non-mock proof → `GraduationNotVerified` = 6036. Confirmed by a test.
