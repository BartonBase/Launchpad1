## New instructions: what each does, and the verdict
Fund-holding accounts and how money can leave them (Barton's top priority):
- **Launch inventory** (`launch_vault` PDA):
  - Tokens: only `buy_inventory` signs with this seed. It works only on Modes 4/5, and only to the treasury.
  - SOL: no instruction moves it out (locked).
- **Mode 2 vault tokens:** unchanged, covered by the existing suite.
- **Mode 3:** holds nothing; tokens are burned.
- **Mode 4/5 lock account:** no outflow at all.
- **Mode 4/5 treasury:** only `claim_tax` and `settle_raffle` pay out. Both are bounded by `credited − paid` and the treasury balance, the amount is fixed by state, and the recipient is fixed (current holder at the cursor, or the snapshotted seat owner).

There are no admin, creator or bot powers over any of these.

**hybrid_launch** (each of the 8 create instructions is a one-shot `init` at the shared `launch_config` seeds, so the modes can't stack; the fee is derived from the ratio tier (`is_exact_tier_fee`); the fee wallet is `PLATFORM_FEE_RECIPIENT`, read-only):

| Instruction | What it does | Verdict |
|---|---|---|
| `launch_plain` (Mode 1) | Classic mint, 1B supply, authorities revoked, `PlainLaunchConfig`; no economics | OK. Native path locks the supply (QA-MOD-04, Info) |
| `register_plain_dbc` (Mode 1) | Binds an allowlisted DBC pool. Pool creator must sign; Token-2022 rejected | OK (engineer tests cover it) |
| `launch_burn` (Mode 3) | Same as `launch`, writes `BurnLaunchConfig` | OK. Native path: QA-MOD-04 |
| `register_burn_dbc` (Mode 3) | Same checks as `register_dbc_launch` | OK |
| `launch_token22` / `launch_raffle` (Modes 4/5, shelved) | Token-2022 mint with locked tax (no fee-config authority). Withdraw authority = vault tax PDA. Tax rate and buyback price come from an allowed set and are locked | OK |
| `buy_inventory` (Modes 4/5) | Tax PDA pays SOL at the locked price; inventory tokens go to ATA(tax PDA) | OK, as long as only hybrid_vault can sign: it requires the T22 config type and `has_one tax_authority`. Tested: attacker signer → 2001; on a Mode 2 vault → 3002. Takes `launch_config` as `mut` without writing it (QA-MOD-02, Info) |

**hybrid_vault:**

| Instruction | What it does | Verdict |
|---|---|---|
| `init_permanent_vault` / `open_permanent_vault` / `wrap_permanent` (Mode 3) | Wrap burns exactly the ratio (user signs) and mints the next NFT (index not chosen by the caller, Merkle leaf checked). Tier fee goes to the fixed wallet. Checks supply after = supply before − ratio | OK. Supply falls only by the burn, by design; no release path |
| `init_token22_vault` / `wrap_token22` (Mode 4) | Locks the ratio in ATA(vault authority) and mints the next NFT. Supply unchanged (checked) | OK. Locked tokens have no outflow |
| `harvest_tax` | Permissionless. Withheld tax → mint → treasury (tax PDA signs); accrues the measured gain | OK |
| `claim_tax` | Pays the round share to the NFT at the cursor, to ATA(current owner). The cursor advances, so it pays once | OK. Tested: non-holder rejected; second claim moves nothing |
| `buyback` | Permissionless. Spends tax-PDA SOL above rent through `buy_inventory`; accrues the gain | OK. LaunchConfig bytes unchanged (tested). SOL is locked in the inventory PDA (QA-MOD-01, Info, ADR-020 open item) |
| `init_raffle_vault` / `init_raffle_randomness` / `commit_raffle` / `reveal_raffle` (Mode 5) | Pinned Switchboard queue. Program picks the oracle (never reused within a round). Fresh randomness required (rand_lock `init`). The reveal is stored and can't be replaced | OK |
| `snapshot_raffle` | Records the owner of the cursor NFT in a dense seat PDA, before any randomness exists | OK |
| `settle_raffle` | Pays the whole pot to the winning seat's snapshotted owner; phase and pot reset, so it pays once | OK |
| `retry_raffle` (fix 2) | After the deadline with no reveal: back to READY (up to 4 commits), then roll back (pot → pending) | OK, no token movement. Selective-reveal grinding is possible (QA-MOD-03, Low, same class as M-04) |
| `skip_dead_nft` (fix 1) | Advances the cursor only if the asset PDA at the cursor is dead (burned or absent). Mode 4 forfeits the share to pending; Mode 5 writes no seat | OK. Can't be aimed at a live NFT (AssetNotDead) or another index (OutOfOrder); engineer fix1 tests cover this |

**Invariants:**
- **Supply conserved:** yes (Modes 1/2/4); Mode 3 burns only the wrapped ratio, by design.
- **Ratio, fees, mint and fee wallet can't be changed:** no instruction writes any config after `init`. All vault outflow instructions take no args, and every `fee_recipient` is the fixed address.
- **Launch vault:** the only withdraw path is `buy_inventory`, Modes 4/5 only.
- **Drain:** nobody can drain or dump program-held funds.
- **No double pay:** prizes and refunds are paid at most once.
- **Stuck-funds fixes:** they can't redirect anyone's funds.
