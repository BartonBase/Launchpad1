B's round-1 fix (c) 's >= k / p_rarest' (p_rarest = 1/N => s = k x N) for comparison, k = 1e-6 SOL:
   R=   10,000 N=100,000: s = 0.1000 SOL  -> largest where m* is ALREADY largest (big N); smallest where m* is smallest (small N). Wrong direction.
   R=   50,000 N= 20,000: s = 0.0200 SOL
   R=  100,000 N= 10,000: s = 0.0100 SOL
   R=  200,000 N=  5,000: s = 0.0050 SOL
   R=  500,000 N=  2,000: s = 0.0020 SOL
   R=1,000,000 N=  1,000: s = 0.0010 SOL
   R=2,500,000 N=    400: s = 0.0004 SOL
   R=5,000,000 N=    200: s = 0.0002 SOL  -> largest where m* is ALREADY largest (big N); smallest where m* is smallest (small N). Wrong direction.

Conclusion printed by the model:
  * m* for the top tier grows linearly with N, so a flat s already scales cost-per-hit with rarity (A is right).
  * Where m* is small (N = 200..2,000, i.e. R >= 500k), F is large and s is a tiny share of the cost: NO flat s
    and NO rarest-tier scaling changes m*; only the token fee does (m* -> 0.02 x N = 4x..40x floor).
